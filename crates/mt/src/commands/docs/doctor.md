## Огляд

Команда `mt doctor` збирає діагностику конфігурації `.mt.json`, робочої теки `mt/` і пов’язаного git-стану проєкту, щоб показати стан готовності середовища до роботи. Публічні точки входу: `DoctorArgs`, `run`.

Окремі локальні fail-safe гілки пом’якшують збої й можуть повертати порожнє значення, зокрема `null`, замість винятку. Інші помилки можуть поширюватися назовні.

## Поведінка

`DoctorArgs` задає порожню форму командних опцій для діагностичної команди, тому поведінка перевірок визначається контекстом запуску та режимом виводу.

`run` збирає діагностичні результати послідовно: спершу намагається знайти робочу теку задач на основі стану проєкту та `.mt.json`, потім, якщо це вдалося, перевіряє належність цієї теки до git-репозиторію й наявність віддаленого `origin`. Кожна перевірка перетворюється на запис зі статусом і поясненням, а невдалі локальні кроки не переривають збір решти доступної діагностики.

Результат іде або в машинний JSON із загальним підсумком, або в текстовий список позначених перевірок для людини. Завершальний статус процесу відображає сукупний стан: успіх лише тоді, коли всі зібрані перевірки успішні; інакше команда завершується з помилковим кодом.

## Публічний API

- DoctorArgs — описує вхідні налаштування команди діагностики.
- run — виконує діагностику .mt.json, `mt/` і git-стану проєкту, щоб користувач побачив проблеми, які заважають коректній роботі інструмента.

## Гарантії поведінки

- Власних операцій запису (ФС/БД) у файлі немає; виклики імпортованих модулів можуть писати.
- Містить локальні fail-safe гілки; інші помилки можуть поширюватися назовні.
- Деякі локальні fail-safe гілки повертають порожнє значення (напр. `null`) замість винятку.
