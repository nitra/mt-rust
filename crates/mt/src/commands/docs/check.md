## Огляд

Файл реалізує one-shot gate для `mt check` — колишнього `mt watch`, який показує, чи є в проєкті задачі або worktree, що потребують перегляду перед продовженням роботи чи в CI. Він звітує про pending-audit без результату, вузли на plan-review, провалені вузли й застарілі worktree, а exit-кодом відрізняє чистий стан від стану, де потрібна увага.

Перевірка працює fail-safe: перехоплює помилки, не кидає винятків назовні і за окремих збоїв повертає порожній результат замість переривання виконання.

## Поведінка

`CheckArgs` позначає запуск перевірки без додаткових налаштувань: поведінку визначає поточний проєкт, режим виводу та стан задач і worktree.

`run` збирає актуальний зріз задач із директорії задач, розгортає дерево у спільний перелік вузлів і з нього формує групи, що потребують уваги: задачі на pending-audit, plan-review і failed. Додатково читає конфігурацію проєкту для порогу застарілості worktree, зіставляє знайдені задачі з worktree репозиторію та fail-safe повертає порожній список застарілих worktree, якщо корінь репозиторію або інвентаризація недоступні.

Результат перевірки йде або в machine-readable JSON, або в текстовий вивід для людини. У чистому стані команда повідомляє, що увага не потрібна; інакше друкує кожну знайдену категорію окремими рядками. Процес завершується з кодом `0`, коли немає pending-audit, plan-review і stale worktrees, та з кодом `1`, коли такі сигнали є. Провалені вузли виводяться й потрапляють у JSON, але самі по собі не роблять стан таким, що потребує уваги для exit-коду.

## Публічний API

- CheckArgs — задає вхідні налаштування для одноразової перевірки уваги/CI-гейта `mt check`.
- run — виконує one-shot перевірку стану: знаходить `pending-audit` без результату, застарілі worktrees, вузли на `plan-review` і failed nodes. Завершується з `exit 0`, коли все чисто, або `exit 1`, коли є що переглянути. Працює fail-safe: перехоплює помилки, не викидає винятки назовні та в окремих помилкових сценаріях повертає порожнє значення на кшталт `null`.

## Гарантії поведінки

- Власних операцій запису (ФС/БД) у файлі немає; виклики імпортованих модулів можуть писати.
- Перехоплює помилки і не пропускає винятків назовні (fail-safe).
