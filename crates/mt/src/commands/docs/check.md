## Огляд

Виконує одноразовий attention-check для `mt check` — колишнього `mt watch`, щоб CLI або CI могли швидко визначити, чи є pending-audit без результату, `stale worktrees`, вузли на plan-review або провалені вузли. `CheckArgs` задає вхідні умови перевірки, а `run` запускає гейт і повертає exit-код: `0` для чистого стану, `1` коли є категорії, що потребують перегляду.

## Поведінка

`CheckArgs` задає порожню конфігурацію запуску: поведінка перевірки визначається поточним проєктом, знайденими задачами, worktree-станом і режимом виводу.

`run` виконує одноразову перевірку уваги для CLI/CI. Спочатку визначається каталог задач, далі збираються пов’язані worktree та дерево задач; дерево розгортається в єдиний список, щоб усі вузли перевірялися за спільними правилами незалежно від вкладеності.

Зі списку задач формуються групи для звіту: очікування audit-результату, очікування plan-review та провалені вузли. Окремо з конфігурації проєкту береться поріг застарілості worktree; інвентаризація worktree повертає застарілі записи.

Результат іде або в JSON, або в людиночитний stdout. JSON містить усі зібрані групи та прапорець потреби уваги. Текстовий режим друкує «чисто — уваги не потребує», коли немає pending-audit, plan-review, stale worktrees і failed-вузлів; інакше виводить знайдені записи за категоріями.

Завершення процесу використовується як CI-гейт: код `0` означає відсутність уваги, код `1` — наявність pending-audit, plan-review або stale worktrees. Провалені вузли потрапляють у звіт, але самі по собі не формують прапорець потреби уваги.

## Публічний API

- CheckArgs — описує налаштування запуску `mt check` як one-shot attention/CI-гейта.
- run — перевіряє стани для звіту: `pending-audit` без результату, stale worktrees, вузли на `plan-review` і провалені вузли. Завершується з exit `0`, коли перегляд не потрібен, і з exit `1`, коли є що переглянути.
